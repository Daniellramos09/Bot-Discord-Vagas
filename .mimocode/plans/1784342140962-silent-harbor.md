# Plano: Corrigir encoding de URL na GitHub Search API

## Problema
A `FerramentaScraper` envia requisições à GitHub Search API com o qualificador `stars:>800`. O caractere `>` precisa ser literal (não codificado como `%3E`) para o GitHub aceitar. Porém:
- `RestTemplate.getForObject(String)` codifica `>` → `%3E` (rejeitado pelo GitHub)
- `URI.create()` com `>` literal lança `Illegal character in query`

## Solução
Configurar o `RestTemplate` bean com `EncodingMode.LITERAL` para que não codifique a URL, e reverter `FerramentaScraper` para usar `String` em vez de `URI`.

## Arquivos a modificar

### 1. `src/main/java/com/github/daniellramos09/discordvagas/config/RestTemplateConfig.java`
- Adicionar import de `DefaultUriBuilderFactory`
- Criar `DefaultUriBuilderFactory` com `EncodingMode.LITERAL`
- Passar como `.uriTemplateHandler(factory)` no builder

### 2. `src/main/java/com/github/daniellramos09/discordvagas/domain/ferramentas/FerramentaScraper.java`
- Reverter `resolveApiUrl()` para retornar `String` (remover `URI`)
- Reverter `scrape()` para usar `String apiUrl` em vez de `URI apiUrl`
- Remover import de `java.net.URI`
- Manter `.replace("%3E", ">")` como defesa para URLs vindas da env var

## Verificação
- Subir a aplicação e verificar no log que a URL contém `stars:>800` (não `%3E800`)
- Confirmar que a busca retorna repositórios sem erro 422
